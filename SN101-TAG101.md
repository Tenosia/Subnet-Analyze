# Tag101 — Subnet 101 (SN101)

**Semantic tagging of X (Twitter) posts.** Repo: `/home/vps-project/tag101` · netuid **101** (finney). *This is the subnet actively mined in this workspace.*

> **Archetype: data / service pipeline** (CPU + LLM API, on-demand). A miner receives a short social-media post and returns **3 topic tags**. Winner-take-most; scoring is **consensus-based** (you're rewarded for predicting what the crowd tags).
>
> Full operator guide with the optimized tagger + local self-scoring tool: [`tag101/docs/SN101_WINNING_GUIDE.md`](../tag101/docs/SN101_WINNING_GUIDE.md).

## Goal
Turn a stream of social posts (currently AI-domain) into a **clean, canonical topic-tag index** through decentralized consensus. Validators reward miners whose tags match the crowd, are grounded in the post, and cover distinct facets.

## What a miner does
- Receives a task (`kind = sn101.tags.v1`) with the post in `TaskEnvelope.payload["text"]`.
- Returns `{"tags": [t1, t2, t3]}` — 3 lowercase canonical tags (1–5 tokens, no URLs/emojis/pure-numbers).
- **No score feedback** to the miner, and other miners' tags are validator-internal (walled off) — you can't see the real consensus, only predict it.
- Runs as a long-lived neuron (Docker), announcing its axon to the task server so it receives tasks.

## Scoring / evaluation
Per tag: **`TagScore = 0.60·consensus + 0.40·validity·diversity`**. Miner score = mean of your 3 tag scores, minus a mild duplicate penalty if ~80+ miners submit the identical set.

- **Consensus (60%)** = `cluster_support × centroid_proximity` (via `all-MiniLM-L6-v2` embeddings + agglomerative clustering, cosine). Tags many miners also pick, phrased canonically (closest to the cluster centroid), win. → **Predict the crowd; use canonical names.**
- **Validity ∈ {0, 0.3, 0.6, 1.0}** = relevance (embedding sim to post) × format tier. → **Ground tags in the post; correct format.**
- **Diversity ∈ [0,1]** = your 3 tags must be mutually distinct (pairwise cosine < 0.55 = full credit; ≥ 0.85 → 0). → **Cover distinct facets.**

Because the crowd is mostly LLM taggers, the consensus term rewards **canonical, obvious tags** over clever ones.

## Hardware / device
- **CPU-only.** No GPU. The local re-ranker loads a small ~80 MB embedding model (`all-MiniLM-L6-v2`).
- Modest RAM (embedding + optional spaCy). Stable network for the LLM API + axon.
- Cost driver is **LLM API spend** at ~15-min task cadence, not hardware.

## Third-party / API dependencies
- An **OpenAI-compatible LLM API** — **OpenRouter recommended** (`OPENAI_API_KEY`, `OPENAI_BASE_URL=https://openrouter.ai/api/v1`, `OPENAI_MODEL`). Best value: `google/gemini-2.5-flash` or `openai/gpt-4o-mini`.
- Bittensor wallet + `btcli`; Docker.
- ⚠️ **This VPS has broken IPv6** — force IPv4 in the HTTP client (`httpx.HTTPTransport(local_address="0.0.0.0")`), or LLM calls hang ~12s per address.

## How to win
1. **Optimized tagger** (`tasks/sn101_reference/core/optimized_miner.py`): ask the LLM for a *pool* of canonical candidates, then locally re-rank/select 3 that are each valid, on-topic (consensus proxy), and mutually distinct — scored with the **same embedding model the validator uses** (no drift).
2. **Model choice:** `gemini-2.5-flash` was the empirical winner here (beat gpt-4o-mini and claude on live incentive). Use a **recent** model so it knows current AI entities.
3. **Test locally before mainnet** with `tools/sn101_selfscore.py` — runs your tagger through the **real** validator scorer against a synthetic field. Iterate until you consistently rank #1.
4. **Uptime is decisive.** Incentive is an EMA — every restart dips it for hours. Leave a working miner alone; that alone roughly doubled incentive here (~0.001 → ~0.0034).
5. **Don't over-engineer.** A heavier "advanced" consensus-attractor pipeline (multi-sample + clustering) tested **worse** (0.756 vs 0.823 self-score) and underperformed live — the simple optimized tagger + gemini + uptime won.

## Realistic ceiling
**Winner-take-most.** The top UIDs (1–22) are early, refined, and immune, capturing ~10–24× a mid-tier miner's incentive. A well-run optimized miner lands in the **upper-middle and climbs**, but reaching literal #1 against entrenched miners is a stretch. Also watch **deregistration**: on a full 256/256 subnet the lowest-incentive non-immune UID is pruned when someone registers — a new UID must climb above the bottom cohort before its ~24h immunity expires.

## Verdict
**Hard to top, easy to run.** Cheap (CPU + a few $ of LLM calls) and the scorer is fully testable offline. The winning formula turned out to be the *simple* one: **optimized tagger + gemini + perfect uptime.** Fancy pipelines lost.
