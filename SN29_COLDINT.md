## What SN29 originally was (historical — not currently running)
Per `coldint_validator/README.md`: "Bittensor COLlaborative DIstributed INcentivized Training" — a fork of Macrocosmos' original pretraining subnet (SN9), created because that design was "somewhat static and lacked the incentive to publish small improvements." The initial (and, per the frozen `competitions.json`, final) competition rewarded miners for improving a model's loss on the [FineWeb-Edu-2 dataset](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu-score-2) — classic collaborative LLM pretraining, in the same lineage as SN9/Zeus-adjacent model-competition subnets. A secondary "Hall of Fame" mechanism let validators route weight to hotkeys that contributed code, bug-fixes, or key research insights — the mechanism now repurposed to hold the single burn entry.

**Historical hardware** (`coldint_validator/min_compute.yml`, from when competitions were live): 4+ CPU cores @ 2.5GHz, GPU required with 24GB+ VRAM, 32GB RAM, 1TB SSD storage, 100Mbps+ down / 20Mbps+ up. Validators were expected to be able to evaluate ~10.5B-parameter models on a single consumer GPU (RTX 4090-class) per subnetalpha's description — consistent with a fine-tuning/eval workload rather than training-from-scratch.

## Why the discrepancy matters
This is the starkest "marketing vs. shipped reality" gap found across this whole subnet-analysis series (compare SN121 Sundae Bar's stale Letta-agent docs, or SN26 Perturb's stale whitepaper numbers) — those were *behind* the current mechanism; SN29's public pages describe a mechanism that, per the subnet's own dynamic-config repo, **isn't running at all**. Possible explanations, none confirmable from these repos alone: the team wound the pretraining competition down to redirect effort into the new Cacheon (SN14) project; the promised "AI Agent Safety & Security" relaunch never shipped as on-chain competitions; or it's paused pending a future relaunch not yet reflected in `competitions.json`. Whichever it is, the burn-only state is directly verifiable on-chain (check `https://taostats.io/subnets/29/metagraph` yourself for current weight distribution) and isn't something to take on faith from either public page.

## If you're still curious about the mechanism (informational only)
- **Scoring** was loss-based on FineWeb-Edu-2: lower eval loss on a fixed, held-out slice of the dataset scored better, in the classic pretraining-competition mold (same family as SN9/Zeus-adjacent designs).
- **Anti-gaming**: `coldint_validator/model/model_updater.py` + `model/storage/` handled model download/validation from HuggingFace repos committed on-chain, with the usual model-copy/plagiarism concerns any pretraining subnet has to guard against.
- **Miner flow**: train/fine-tune a model, upload to HuggingFace, commit the repo reference on-chain (`neurons/miner.py`), similar in shape to Affine's (SN120) HF-commit pattern.
- None of this is worth setting up today given the confirmed burn-only state — treat this section as historical record, not a setup guide.

## Verdict
**Do not mine or validate here right now.** The subnet is technically live on-chain (registered, has a netuid, presumably still has registered neurons) but is economically inert — every validator following the published dynamic config burns 100% of weight to a single address, meaning no miner effort earns emissions regardless of quality. Before committing any resources, verify current status yourself at `taostats.io/subnets/29` and in the `coldint/sn29` repo's `competitions.json` (still `{}` as of this analysis) — if that ever repopulates with real competitions, this write-up's "dormant" conclusion would need to be revisited, but there is no evidence of that as of this check.
